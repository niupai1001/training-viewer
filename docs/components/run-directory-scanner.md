# 组件说明：运行目录扫描器（RunDirectoryScanner）

## 一句话说明

从用户添加的根目录递归寻找 Run 目录，返回发现的 Run 与目录级问题；不读取指标内容、不写数据库、不修改目录。

## 基本信息

| 项目 | 内容 |
|---|---|
| 中文功能名 | 运行目录扫描器 |
| 代码类名 | `RunDirectoryScanner` |
| 源文件 | `src/training_viewer/discovery/run_directory_scanner.py` |
| 所属模块 | 目录发现 |
| 上游 | `TrainingViewerService.synchronize()`；下游 | `SourceAdapterRegistry`、`TrainingMetricIndexer` |
| 首次引入版本 | 1.0.0 |

## 为什么需要它

用户可能把整个研究目录或磁盘目录加进来。查看器需要在不跟随符号链接、不进入依赖目录、不扫描产物子目录的前提下找到运行。把规则集中在扫描器里，可以防止某个项目目录拖慢全局扫描，也避免路径越界。

## 输入与输出

| 方向 | 名称 | 类型 | 说明 | 错误时 |
|---|---|---|---|---|
| 输入 | `root_directory` | `Path` | 用户显式添加的绝对目录 | 不存在 → 问题 |
| 输出 | `runs` | `DiscoveredRun` 列表 | 每个匹配的 Run | 坏 run.json → 问题，不返回 Run |
| 输出 | `issues` | `ScanIssue` 列表 | 路径、消息、级别 | — |
| 输出 | `scanned_directory_count` | `int` | 本次检查的目录数 | — |
| 输出 | `truncated` | `bool` | 是否达到目录上限 | 记录警告，不静默截断 |

## 主要处理流程

1. 检查根目录存在且是目录。
2. 使用显式栈做深度优先遍历（排序后入栈，结果可复现）。
3. 对每个目录依次询问来源适配器；命中则记录 Run 并**不再深入**（产物目录不会被扫描）。
4. 适配器抛 `InvalidRunDirectoryError`/`ReaderUnavailableError` → 记录问题，停止深入该目录。
5. 读取子目录列表：跳过隐藏目录、`.git`、`node_modules`、`.venv`、`__pycache__` 等；不跟随符号链接目录。
6. 超过深度 12 层或单根目录 50000 个目录时停止并记录警告。
7. 返回发现结果。

## 配置与依赖

| 配置项 | 默认值 | 修改方式 |
|---|---|---|
| `max_directories` | 50000 | 构造参数 |
| `max_depth` | 12 | 构造参数 |
| 排除目录名 | 见 `EXCLUDED_DIRECTORY_NAMES` | 修改常量（需要评审） |

依赖：来源适配器注册表。无第三方依赖。

## 和旧实现相比改变了什么

初始实现。V1 明确“命中 Run 后不扫描其 artifacts/”“不跟随符号链接目录”“扫描上限必须报警而非静默”三条边界。

## 如何验证

- 扫描逻辑由 `test_indexing.py` 的多个集成测试覆盖（标准目录、CSV 目录、冲突目录、移动目录）。
- 手工：添加 `examples/`，应发现 4 个示例运行，而不是把 `artifacts/` 当作运行。
- 深度/数量上限尚无专门测试；修改默认值时应补充。

## 已知限制与回退

- 每 2 秒完整扫描一次根目录；超大目录树可能造成 I/O 压力，应缩小根目录。
- 隐藏目录一律跳过；如果运行位于隐藏目录，需要移动到非隐藏目录。
- 回退：移除根目录即可停止扫描，不影响磁盘文件。

## 名称解释

- 深度优先遍历：先进入子树再返回的遍历方式。
- 符号链接：指向另一个路径的特殊文件；扫描器不跟随目录符号链接。
