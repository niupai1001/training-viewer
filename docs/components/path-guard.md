# 组件说明：路径安全守卫（path_guard）

## 一句话说明

判断协议中的产物路径是否安全，并把相对路径解析为 Run 目录内的真实文件路径；不读取文件内容，也不负责 HTTP 权限判断。

## 基本信息

| 项目 | 内容 |
|---|---|
| 中文功能名 | 路径安全守卫 |
| 代码函数 | `is_safe_relative_path`、`resolve_artifact_path`、`is_path_within` |
| 源文件 | `src/training_viewer/security/path_guard.py` |
| 所属模块 | 安全 |
| 上游 | 标准读取器、索引器、产物 API、校验器；下游 | 文件系统 |
| 首次引入版本 | 1.0.0 |

## 为什么需要它

`events.jsonl` 可由训练程序或第三方工具生成，属于不可信输入。若直接把 `path` 拼到 Run 目录后打开，就可能读取 `C:\Windows\...`、训练目录外的文件，或通过符号链接逃逸。请求参数同样不可信，即使数据库被篡改也不能绕过检查。

## 输入与输出

| 方向 | 名称 | 类型 | 说明 | 错误时 |
|---|---|---|---|---|
| 输入 | `value` | 字符串 | 协议中的相对路径，允许 `\` 并规范化为 `/` | 返回 false |
| 输入 | `run_directory` | `Path` | Run 根目录 | — |
| 输出 | `bool` | 布尔 | 是否安全 | — |
| 输出 | 解析路径 | `Path` | 位于 Run 目录内的真实路径 | `UnsafeArtifactPathError` |

## 规则

拒绝：

- 空字符串、含 NUL；
- 绝对路径（`/...`、`C:\...`、UNC 路径）；
- 任意 `..` 路径段；
- 以 `~` 开头的用户目录展开；
- 解析后（含符号链接）不在 Run 目录内的路径。

允许：

- 使用 `/` 或 `\` 的相对路径；
- 带空格、中文的文件名；
- 指向 Run 目录内部的符号链接（解析后仍在目录内）。

## 主要处理流程

1. 统一分隔符并去除首尾空白。
2. 检查盘符、绝对路径、`..`、NUL。
3. `resolve()` Run 目录与候选路径（解析符号链接）。
4. 使用 `Path.is_relative_to` 确认候选路径仍在 Run 目录内。
5. 返回解析后的路径；否则抛出中文错误。

## 配置与依赖

无配置项。依赖 Python 标准库 `pathlib`。

## 和旧实现相比改变了什么

初始实现。V1 把“只检查字符串”升级为“字符串检查 + 真实路径解析 + 根目录校验”三层，API 层还额外确认 Run 目录属于已注册根目录。

## 如何验证

- `tests/test_security.py`：安全/不安全路径、`..`、盘符、符号链接逃逸（环境不允许创建符号链接时跳过）。
- `tests/test_api.py::test_artifact_path_traversal_is_rejected_even_if_database_is_tampered`：数据库篡改后仍返回 403。
- `tests/test_validation.py::test_artifact_path_traversal_is_error`。

## 已知限制与回退

- Windows 符号链接测试在缺少权限时会跳过；Linux/macOS 会实际执行。
- 不做文件内容类型嗅探，MIME 白名单在 API 层处理。
- 回退：该组件只读，不产生数据变更。

## 名称解释

- 目录穿越：使用 `..` 访问父目录。
- 符号链接：指向另一个路径的特殊文件。
- NUL：空字符，通常用于截断路径解析。
