# 组件说明：索引查询（IndexQueries）

## 一句话说明

把 SQLite 中的运行、指标、事件和产物转换成页面与导出器需要的字典结构；不读取原始日志、不写数据库、不修改索引。

## 基本信息

| 项目 | 内容 |
|---|---|
| 中文功能名 | 索引查询 |
| 代码类名 | `IndexQueries` |
| 源文件 | `src/training_viewer/indexing/index_queries.py` |
| 所属模块 | 查询 |
| 上游 | `TrainingViewerService` / FastAPI 路由；下游 | REST JSON、导出器 |
| 首次引入版本 | 1.0.0 |

## 为什么需要它

如果 API 路由直接拼 SQL，安全校验、分页、降采样和可比性规则会散落在各处。本组件集中实现只读查询，并保证“Best/Last 使用原始数据”“不插值”“可比性警告”这些语义在运行详情和实验对比中一致。

## 输入与输出

| 方向 | 名称 | 类型 | 说明 |
|---|---|---|---|
| 输入 | `run_id` / 筛选参数 | 字符串、数字、布尔 | 来自 HTTP 查询参数 |
| 输入 | `series` | `phase/metric_name` 列表 | 指标身份 |
| 输入 | `axis` | `global_step` / `epoch` / `timestamp` / `auto` | 曲线横轴；`auto` 按每个指标真实字段选择 |
| 输入 | `max_points` | 整数（10–20000） | 返回点上限 |
| 输出 | 运行摘要列表 | `dict` | 项目、状态、主要指标、Best/Last 等 |
| 输出 | 运行详情 | `dict` | 元数据、配置、指标键、会话、数据源、警告 |
| 输出 | 曲线 | `dict` | 系列、点、总数、是否抽样、Best/Last、警告 |
| 输出 | 对比 | `dict` | 每个指标的运行曲线、可比性、超参数差异 |
| 输出 | 产物分组 / 时间线 / 诊断 | `dict` | 页面直接消费 |

## 主要查询能力
- `projects()`：项目/实验组树、运行数、运行中数量、根目录。
- `list_runs()`：项目、实验组、状态、标签、任务、模型、数据集、收藏、搜索；分页与排序；主要指标与 Best/Last。
- `get_run()`：元数据、模型/数据集/来源、指标键、会话、产物标签、数据源游标、问题、Step 回退、警告。
- `query_series()`：单运行多指标曲线；`axis=auto` 为每个指标选择真实存在的横轴，按会话返回 `session_id`，前端据此分段。
- `compare()`：多运行、多指标；不同任务/单位/数据集/定义产生警告；计算超参数差异；缺轴时警告但不插值。
- `list_artifacts()` / `artifact_groups()`：产物清单与按 `group_id` 聚合的角色。
- `timeline()`：生命周期、心跳、产物事件合并排序。
- `diagnostics()`：目录级问题、run_id 冲突、问题运行。
- 备注、收藏、保存的对比视图（支持按 id 取回完整 payload）。
- 运行摘要/详情返回独立的 `activity`/`activity_label`；活动只表示最近是否有新指标，不证明进程存在。

## Best / Last 与降采样

- **Best**：仅在指标定义 `direction` 为 `min`/`max` 时，用 SQL 对**全量原始点**排序取首条。
- **Last**：`ORDER BY timestamp IS NULL, timestamp DESC, id DESC LIMIT 1`；无时间戳时按写入顺序。
- **降采样**：返回点数超过 `max_points` 时按分桶保留首尾/最小/最大；`total_points` 仍为真实数量，`downsampled` 标记是否抽样。
- **不插值**：某运行缺指标时，对比结果的该运行没有点，并产生警告。

## 可比性规则

对每个指标收集：

- 单位（`unit`）；
- 数据集名称/版本/划分；
- 指标定义、聚合、比较键；
- 任务类型；
- 是否有 min/max 方向。

任一维度不一致 → 产生对应警告；`ranking_allowed` 仅在所有运行单位、数据集、定义、任务一致且都有方向时为 true。即使不可排名，曲线仍会绘制，由用户自行判断。

## 配置与依赖

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 列表分页 | 200，最大 1000 | API 参数 |
| 曲线返回点 | 详情 3000、对比 1500（上限 20000） | API 参数 |
| 超参数差异上限 | 500 行 | 防止异常配置撑爆页面 |
| 时间线上限 | 5000 条 | API 层截断 |
| 诊断问题上限 | 500 条 | API 层截断 |

依赖：`IndexDatabase`（SQLite）、JSON、标准库。所有 SQL 使用参数绑定，不拼接用户输入（排序字段使用白名单）。

## 和旧实现相比改变了什么

## 如何验证

- `tests/test_api.py`：筛选、详情、曲线三种横轴、对比、导出、产物、诊断、备注、保存视图。
- `tests/test_downsampling.py`：抽样点包含极值，Best/Last 为原始值。
- 手工：对比 `segformer-baseline` 与波长编码运行，应显示 `val/miou` 0.52 vs 0.61，Best 步骤分别为 200/400。

## 已知限制与回退

- 无缓存；每次请求重新查询 SQLite。本地规模可接受。
- 时间线/诊断只返回有限条数，更早记录需要直接查询数据库或后续加分页。
- 运行列表的“主要指标”是启发式选择，不等同于研究结论；用户应在运行详情或对比页明确选择指标。
- 回退：查询层只读，回退代码不会损坏数据。

## 名称解释

- 降采样：减少返回点数量，但保留极值。
- 可比性：单位、数据集和指标定义足以支持直接比较的条件。
- 主指标（primary metric）：运行列表中用于摘要展示的指标，不代表训练程序的最优指标。
