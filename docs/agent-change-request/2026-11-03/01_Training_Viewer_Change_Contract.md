# Training Viewer 修改契约（强制执行）

> 契约编号：TV-CHANGE-2026-11-01  
> 文档版本：1.1（2026-11-03 补充海量指标选择；本文件版本不代表 TVLP 日志协议版本）  
> 适用对象：Training Viewer 开发 Agent、Code Reviewer、训练代码接入 Agent  
> 对应仓库：[niupai1001/training-viewer](https://github.com/niupai1001/training-viewer)  
> 审计基线：`405e2a52712f8a826e53b28ae5f89050f2feb8ed`。开始实施时首先核实 HEAD；若有更新，以实际代码为准重新核对本文引用。  
> 目标：在**不破坏已有日志、不要求训练端接入服务**的前提下，实现真正默认可用、科学可读、界面专业的本地深度学习训练查看器。

## C0. 契约解释、优先级与完成定义

本文件的“必须 / 禁止 / 应当 / 可以”具有不同约束强度：“必须”和“禁止”是验收门槛；“应当”允许有证据的技术替代；“可以”属于可选扩展。发现与现有设计冲突时，记录冲突、影响、备选方案和兼容性，不得静默降低要求。

以下问题属于 **P0 阻断项**，任一项未通过，不得宣称本轮交付完成：

1. 不经手动选指标，打开真实 Run 即能看到**训练时间信息、进度、Train Loss、Validation Loss（如果真实存在）、主验证指标和当前学习率（如果真实存在）**。
2. Loss 早期极大、后期很小时，用户能够明确看清后期变化；显示模式不更改或伪造数值，不隐藏聚焦事实。
3. 指标主名称具有可读解释；`train/epoch_QUIVALENT` 之类未知字段不被猜测成权威含义。
4. 新的标准训练日志遵循结构化“四要素实验描述”与指标定义；旧 TVLP 1.0、旧 CSV/JSONL/TensorBoard **继续读取**，原始日志只读。
5. 单工作区交互真实简化：**唯一实验侧栏、默认一张 Train/Val Loss 同图、主验证指标图、按需打开高级分析**；不得用折叠旧表单冒充重新设计。
6. 日志追加能够刷新曲线，与训练状态是否为 `running` 解耦；不可因为无心跳或导入日志而冻结。
7. 当单个 Run 存在数百或数千指标时，默认页面不得平铺所有字段为按钮；必须提供可搜索、分组、渐进加载的指标目录，支持用户主动添加并持久化自定义图表；单点评估结果不得伪装为训练曲线。

项目不承担训练、模型推理、在线多用户服务、远程服务器连接或完整 MLOps 编排。除显式批准外，不引入与本地只读查看无关的服务、认证或持久化双轨系统。

## C1. 日志与研究数据完整性契约

- 原始文件是唯一事实来源；Viewer 的 SQLite 索引可删除重建；用户补充的显示名、指标说明、收藏等持久状态存放 Viewer 独立数据区，不能写回历史日志。
- 原始记录的数值、时间戳、Step、Epoch、Phase、Session 必须保持一致；不补 0、不从 Loss 计算 mIoU、不对不存在的验证指标做推断、不自动归一化跨实验数值。
- 同一个指标的 Train、Val、Test 阶段必须区分；验证指标不能用测试集指标替代。Epoch/Step 及时间必须保留原始语义。
- 不同单位、损失函数、数据集划分或聚合方式的指标不能静默叠加、排名或聚合。可显示并提供“不具直接可比性”说明。
- 缺失原因至少区分：`not_logged`（未记录）、`not_defined`（记录但未定义含义）、`not_parsed`（识别失败）、`not_comparable`（不可直接对比）。不能统一展示成 0 或“训练失败”。
- 图表平滑、降采样和纵轴聚焦只能影响显示，不得修改 Best、Last 及原始记录；导出应说明当前显示模式和原始数据范围。

## C2. 默认监控摘要契约：不是“可选指标”

### C2.1 统一后端模型

增加聚合服务 `RunMonitoringSummary`，后端返回经语义识别后的数据，前端不再通过随意匹配字段名称自行拼凑：

| 字段 | 显示名 | 来源/规则 | 没有数据时 |
|---|---|---|---|
| `activity` / `status` | 数据更新情况 / 训练状态 | 文件更新证据与事件生命周期分别判断 | “未知”，不伪称运行中 |
| `timing.active_training_seconds` | 累计运行时长 | 可靠的 `started/resumed` 与停止事件分会话累计；开放会话需可信活动证据 | “未记录” |
| `timing.wall_span_seconds` | 训练/日志时间跨度 | 有可信 started/ended 事件用事件跨度；否则只用日志首末时间戳并标记日志跨度 | “未记录” |
| `current_epoch` / `planned_epochs` | 已训练轮次 / 计划轮次 | 日志与配置分别提供 | `—`，不默认 0 |
| `current_global_step` | 当前优化步 | 真正优化器更新步 | `—` |
| `train_loss.latest` | 最新训练损失 | 明确的训练阶段损失 | “未记录” |
| `val_loss.latest` | 最新验证损失 | 明确的验证阶段损失，不能用 Test Loss 顶替 | “未记录” |
| `primary_validation_metric.best` | 最佳验证指标 | `is_primary` 优先，可靠别名次之；依定义方向评优 | “未定义/未记录” |
| `learning_rate.latest` | 当前学习率 | 最近对应参数组 LR；多参数组区分 | “未记录” |
| `last_log_at` | 最新日志时间 | 最近完整、合法数据/事件时间 | “未记录” |

**计时严禁误导：** 当前 `index_queries._time_ranges()` 用指标最早与最晚时间戳的差计算 `duration_seconds`，该值不能叫“实际训练时长”。新设计明确标记 `timing.source`（`lifecycle_events`、`metric_timestamps`、`unavailable`）及 `timing.quality`；断点续训的长时间暂停不得算入累计有效训练时长。没有结束事件时不得简单将最后一个指标与当前时间差无限累加成“正在训练”。

### C2.2 页面默认显示顺序

1. 首行：统一实验名、状态、最近更新、可展开的完整四段说明。
2. 第一屏六个信息位置：**累计有效运行时长／日志跨度**（明示类型）、Epoch/Step、最新 Train Loss、最新 Validation Loss、最佳主验证指标、Learning Rate；真实缺失显示原因。
3. 一张 Train + Val Loss **同图**（存在且可比较时）；验证数据点稀疏要保留实际位置，不插值制造新点。
4. 一张主要验证指标图（mIoU/Accuracy/F1 等，优先级须由任务及元数据决定）；学习率可用轻量趋势组件，不占用损失图位置。
5. 下方是预测结果 / 标签对照和更多分析。原始字段表、文件游标与复杂设置不占默认首屏。

Loss 定义不兼容时必须分开图或明确警告。仅有 Train Loss 时显示它，并在摘要明确“未记录验证损失”。

## C3. Loss 纵轴与图表交互契约

### C3.1 当前证据

`frontend/src/components/MetricChart.tsx` 已有 ECharts `yAxis.scale: true`，但 `dataZoom.filterMode: 'none'`、前期巨大值与默认全程显示，使后期变化难辨。解决方案是**可验证的纵轴行为**，不是把字体放大或删除最初极值。

### C3.2 交互模式

| 模式 | 约束 |
|---|---|
| 全程 | 原始数值和真实范围完整可见；所有点参与尺度确定；恢复默认图形范围 |
| 后期聚焦 | 以最后 20% 的**有效横轴范围**为初始焦点（不可只凭数组尾部 20%），根据窗口内各可见系列的真实值计算 Y 范围并留合理边距；可自定义；明确显示“后期聚焦/局部放大” |
| 对数 | 对全部可绘制值严格大于 0 的系列提供 log Y；出现零/负值时不应强行取对数或丢点，应解释不可用并保留线性图 |
| 自定义 | 用户可设 X/Y 范围，并一键恢复；记录到可恢复视图 |

对全程值跨度特别大的正 Loss，可以**建议**后期聚焦或对数模式，但不可悄悄更改 Y 轴或隐瞒早期数据。聚焦模式可增加迷你全程概览。两个实验直接比较时，必须共享同一量纲和轴范围；不得为两条 Loss 曲线各用独立自动 Y 轴再宣称它们可直接比较。

实现应明确处理 ECharts `dataZoom` 的窗口与 Y 轴相互作用：`filterMode:'none'` 不保证按 X 窗口重算 Y；可通过服务端窗口查询结合显式 Y 轴范围计算，或评估 `filterMode:'filter'`，但都必须验证数据点不被误删、不会产生图表缩放事件反馈循环。保留未缩放视图的完整数据范围。

单一点、少于 3 点、常数序列、全零、正负混合、初始 100 倍极值、长尾渐进下降、断点续训和分桶降采样均必须测试。纵轴标签不得将不同数值四舍五入成完全相同的文字。

## C4. 指标语义与解释契约

### C4.1 统一语义对象

新增 `MetricSemanticResolver`（中文：指标语义解析器）。`MetricSemantics` 至少包括：

`raw_key`, `phase`, `display_name_zh`, `display_name_en`, `category`, `description`, `definition`, `unit`, `direction`, `aggregation`, `comparison_key`, `source`, `confidence`, `is_primary`, `default_visibility`。

建议分类：`loss`、`validation_score`、`learning_rate`、`training_progress`、`performance`（吞吐量/耗时）、`system`、`custom`。同名指标的 Phase、单位、聚合方法和计算定义仍需核对。

解析优先级：**标准日志明确声明 > 用户在 Viewer 中确认的项目/运行级覆盖 > 安全内建别名词典 > 未知原始字段**。后两者不可以覆盖前两者。解析结果应显示来源：`declared`、`user_override`、`builtin_alias`、`unknown`。

### C4.2 禁止未经证明的指标解释

`train/epoch_QUIVALENT` 是非标准字段，在未查到训练代码或原始定义前，不能擅自称为“等效 Epoch”并断言其公式、单位或意义。显示为“未定义指标”，并保留原始键名，提供“填写定义”入口。只有明确公式后才允许翻译并归类到训练进度。

常见内建别名可以解释一般含义，但不能自动推断损失函数的组成、mIoU 的 ignore_index、F1 的 averaging、学习率的参数组等专属定义。

前端标签呈现：**中文可读名为主，阶段作为小型辅助信息，ⓘ 查看完整解释，原始键在详情中保留**。无意义的大写缩写不能直接进入首页 KPI。指标词典允许插件扩展，不要求每个训练项目安装额外 Python 包。

## C5. 实验命名与 TVLP 协议升级契约

### C5.1 新标准实验“四要素”

新规范化训练 Run 必须提供**四个独立、具有自然语言意义的字段**：

1. `data_description`：数据源、必要的波段/分辨率/版本/划分。
2. `model_architecture`：模型家族、骨干网络及对比涉及的关键结构。
3. `modification_plan`：相对基线真正修改了什么；基线写“原始基线，无结构改动”。
4. `research_objective`：本次训练要验证的科学或工程假设，不能只写“实验/测试/obs”。

建议新增 `experiment_description` 对象保存四项，另有可选 `change_details` 记录组件级变化。`name` 从四要素生成**有长度控制的可读摘要名**，完整四段始终可展开；严禁手工任意填写 `obs`、`run1`、`V3` 或不带模型的中文描述作为新标准 Run 的正式名称。允许人工修改展示别名，但保留原始四段结构且不改变稳定 `run_id`。

**姓名（name）不是身份（run_id）。** run_id 必须稳定且唯一；断点续训复用 run_id 并另建 session_id。历史导入文件名不得用于冒充真实模型架构。来自 CSV/文本的未知信息显示“未提供”，可在 Viewer 独立用户数据区补充并标明来源。

### C5.3 版本兼容策略

- 保留 TVLP 1.0 Schema 原文件和语义，不得直接把现有 `1.0` 校验规则改成更严格的 1.1。
- 另建 1.1 Schema，`RunMetadataReader` 根据 `schema_version` 分流，Writer 在明确 1.1 输出时满足新增必填约束，校验器同时识别 1.0 / 1.1。
- 标准 v1.1 的四段说明及主要指标描述必填；指标可有任意自定义名称，不强制每个指标都有 `direction=min/max`，无优化方向用 `none`。
- 既有 TVLP 1.0 与历史 JSONL/CSV/TensorBoard 只读导入继续成功，无须修改历史文件。旧版元数据缺失时显示“未提供”，不可让导入失败。
- 同步更新 **源码中的 Schema 副本、JSON 校验器、Writer、API/TypeScript 类型、SDK 示例、`AGENT_INTEGRATION.md`、术语表与训练 Agent 规范**；不能只改 README 或 UI。
- 每份契约变更必须同时增加正例、反例、旧版本兼容测试和 `docs/changes` 记录。

## C6. 新前端设计契约

### C6.1 只保留一套导航

桌面版默认**一个 340–420px 可调整宽度的实验侧栏**（不超过页面宽度约三分之一）。去掉 AppShell 的重复项目树与内嵌第二级实验栏。实验卡可显示 2–3 行标准摘要名、模型/数据关键词、状态、最新核心指标；点击卡片切换主实验，使用明确的“加入比较”控制进入多运行比较。不要把单击行为和多选行为混为一谈。

主区顺序固定为：实验标题与简要四要素 → 六项监控 KPI → Loss 同图 → 主验证指标图 → 预测图与标签 → 高级分析入口。桌面优先使两张图并排或采用主次自适应布局；图表必须具备足够可读面积。小屏可折叠实验栏，不能横向溢出。

默认页面**不得**存在全宽横轴/平滑/窗口/对数/原始图等配置条；图表右上角放轻量 `全程 / 后期 / 对数 / 更多`。不默认呈现大面积原始数据表、Schema 版本、游标偏移、源文件清单、重复的 PNG/SVG 按钮和长篇技术说明。这些能力不删除，统一移入导出菜单、指标说明 Popover 或高级面板。

### C6.2 统一设计系统与成熟开源组件

推荐只选择**一种** UI 组件体系：首选 `shadcn/ui + Radix + Tailwind`（由 Agent 结合构建成本做小型样例后落地），或确有依据时选 Mantine，但不得两个体系长期并用。优先复用：

- `shadcn/ui`：Tooltip、Popover、Sheet、Dialog、Dropdown、Command、Skeleton、Tabs、Sidebar 的成熟交互与可访问性；[GitHub](https://github.com/shadcn-ui/ui)。
- `react-resizable-panels`：实验栏宽度调整与折叠；[GitHub](https://github.com/bvaughn/react-resizable-panels)。
- `Apache ECharts`：**保留现有曲线引擎**，只重写比例尺、交互和布局；[GitHub](https://github.com/apache/echarts)。
- `TanStack Table`：高级实验参数对比、排序与分页；[GitHub](https://github.com/TanStack/table)。
- `Lucide`：统一图标，不再混用文字符号及平台依赖图标；[GitHub](https://github.com/lucide-icons/lucide)。
- Aim / MLflow / Grafana：研究信息架构、曲线探索和对比交互，**不要**因视觉重构直接引入整个服务端；[Aim](https://github.com/aimhubio/aim)、[MLflow](https://github.com/mlflow/mlflow)、[Grafana](https://github.com/grafana/grafana)。

复用代码必须核查指定版本许可证、依赖、安全公告和 NOTICE/版权归属。优先通过依赖安装或官方组件生成流程采用；不盲目复制大段不同许可证源代码。现有 `frontend/src/styles.css` 近三千行，迁移完应删除废弃选择器，不能无限制叠加覆盖层。

### C6.3 视觉与易用性标准

- 定义一套 Design Tokens：文字大小/行高、间距、颜色、边框、焦点环、状态色、暗/亮主题；既不是默认浏览器控件，也不是所有信息塞进白卡片。
- 文字层次清晰：KPI 数值突出，说明文字退后，实验名多行可读；长标题在列表显示 2–3 行，详情提供全称，不丢失四要素。
- 鼠标和键盘均可完成切换实验、打开指标解释、图表缩放恢复和加入对比；焦点可见；重要状态不用颜色作为唯一编码。

## C10. 海量指标选择、曲线与结果分流契约（新增，P0）

### C10.1 触发该修改的实际问题

2026-11-03 的真实界面截图显示同一个运行中有 `capacity/*`、`combo_SWIR_pair/L8/SR_B6/{bias,mae,nmse,rmse}`、`train_A`、`val_A` 等众多指标键。当前 `RunMetricsTab.tsx` 通过 `metric_keys` 逐项生成可选按钮，`MAX_SELECTED_METRICS` 限制六项，默认 `chartLimit` 还可能截断选中指标。这使用户必须在大量英文原始键名中寻找曲线，并且将**只有一个点的组合评估**混入**连续训练趋势**。截图中不少 `combo_*` 指标每项仅 1 点；这种数据不应该默认作为折线曲线。

本契约要求区分三件事：**数据字段**（可访问、可搜索）、**可绘制的数值序列**（具有合适横轴和足够的不同横坐标）和**图表视图**（用户希望组合哪些系列、以何种方式显示）。三者不等价。

### C10.2 默认首页与指标浏览器分离

1. 默认工作区只显示用户最常见的核心监控：Train/Val Loss 同图、明确的主验证指标、必要的学习率与训练时间摘要。其他指标的数量不应改变默认首页复杂度。
2. 在图区提供单一、明显的 `＋ 添加图表 / 指标` 入口，打开**侧滑指标浏览器**。不得在主图区之上铺满所有指标名称的按钮或 Phase 标签。
3. 指标浏览器拥有固定的搜索框，支持搜索：中文显示名、英文原始键、解释文本、指标分组、路径片段；搜索大小写不敏感。返回结果必须显示总命中数和已选数。
4. 用清晰的层级进行筛选：**训练与验证趋势**、**资源/吞吐性能**、**单次评估及组合结果**、**其他未分类字段**。阶段 Train、Val、Test 是单独的筛选维度；`capacity`、`combo_SWIR_pair` 这样的路径前缀不能擅自当成训练阶段。`train_A`/`val_A` 等陌生名称也不能仅凭前缀确定语义。
5. 对具有结构层级的原始键按 `/` 分组，但原始 key 保留且可一键复制。例如 `combo_SWIR_pair → L8 → SR_B6 → mae`。仅凭分段不能断定 L8、SR_B6 实际代表什么传感器/波段：具体维度说明来自训练日志明确的 `metric_groups`、用户确认映射或经核验的项目代码。
6. 每项显示：**可读名称、原始 key（次要信息）、实际数据点数、可用横轴、单位、趋势/单点分类、语义说明来源**。未知含义必须用“定义未提供”标记，不能臆造。
7. 指标浏览器可以任意选择符合条件的数值序列并点击“添加为新图”或“加入当前图”。不允许用固定六项上限阻止科研指标分析；对单张图太多系列时提供性能警告、建议拆图，但不能丢弃已选字段。
8. 已选项必须始终有清晰的可见结果：选了几项就呈现几项，或通过明确提示说明哪些项转为表格/散点；不得出现“已选 6 项，实际只画 2 项”的隐藏截断。
9. 用户可移除图表、修改标题、重新排序、选择 X/Y 轴模式；自定义图表配置保存在 Viewer 用户状态区，按 Run/项目视图区分，并能在页面重启后恢复。配置引用稳定原始指标 key，不用中文名作为标识。重建索引后应恢复或说明丢失字段。

### C10.3 数据类型判定与专用展示方式

后端建立 `MetricCatalogItem`（指标目录项），含：
`raw_key`、`phase`、`semantic_group`、`display_name`、`description`、`definition_source`、`unit`、`direction`、`point_count`、`distinct_x_count`、`available_axes`、`value_kind`、`suggested_view`、`group_path`、`is_primary`。分类以协议声明为先，数值行为只用于选择**适合的图形**，不能用于推断科学含义。

| 原始数据性质 | 默认表现 | 强制行为 |
|---|---|---|
| 两个及以上**不同有效 X 值**的标量序列 | 折线曲线候选 | 保留原始时间轴/Step/Epoch；2 点仅代表两点连线，不能宣称趋势可靠；重复 X 不制造趋势 |
| 仅一个有效 X 值，或无时间/Step/Epoch 但有单次数值 | 数值卡片、可筛选评估表、散点 | 不列为推荐训练折线；仍可搜索、查看、导出，不能丢弃 |
| `capacity/*` 等吞吐和资源数字 | 性能指标分组 | 仅在定义明确时显示“吞吐量”“GPU 显存”；不同单位不能强行叠加 |
| `combo_SWIR_pair/...` 等成批的同结构单点评估 | 组合结果表格，维度声明充足时可转热力图 | 应在同一组中按原始路径列出值；MAE/RMSE 等是否可比较必须看定义、单位与数据集 |
| 无法识别的指标或无有效横轴 | 其他指标/原始数值 | 如实提示原因，提供映射入口，不推算曲线 |

数据展示形态允许用户手动覆盖，但禁止把用户选择的“折线”解释成训练结果确实存在连续变化。单点可绘制为**散点或标记**，并显示“仅 1 个数据点”。

### C10.4 分组、保存、多实验对比与性能

- 指标目录查询必须支持**服务端搜索、分组计数、分页或游标增量获取**；初次加载不要一次性渲染数百/数千按钮。建议每批 30–100 项，界面列表需要虚拟化/增量渲染。对于 1,000+ 指标场景必须实际测量加载和搜索响应。
- 建议 API：`GET /api/runs/{run_id}/metric-catalog?query=&category=&phase=&value_kind=&group=&limit=&cursor=`，并与已有运行/指标 API 兼容。不要为了简单的搜索引入与本地工具不相称的新搜索服务。
- 多项选择与图表类型解耦：用户明确把相容单位、同一横轴语义的指标合并一图；如量纲不相容则分图或给出显式拒绝原因，不用双 Y 轴掩盖差异。
- 单次评估的系列可在表格和热力图中横向比较不同组合；热力图需要经过确认的维度解释，不能把目录名猜测成科学标签。
- 跨实验对比用**可证实的相同指标定义/比较标识**匹配，不能仅对英文字符串按名字拼接。缺项不做插值，不自动补零。
- 自定义视图和用户补充解释必须写入独立用户状态库，与可重建指标缓存分离；重新导入、切换实验、刷新或重启服务后不能丢失布局与选择。
- 搜索过滤应适用中文别名和原始字段；搜索词变化期间不得清空当前选中集合。用户通过“查看全部原始指标”永远可以访问全部字段。

### C10.5 TVLP 1.1 元数据契约补充

新标准日志的 `metric_definitions` 应支持可选的 `category`、`semantic_group`、`suggested_view`、`default_visibility`，并保留已有 `display_name`、`description`、`definition`、`unit`、`direction` 等字段。对大量结构化组合结果，可提供可选的 `metric_groups` **显式分组说明**（例如路径前缀、组名称、维度标签），避免每个组合重复定义。具体 JSON Schema 应在 1.1 尚未发布时一次定稿，并增加版本测试，不得偷偷修改已固定的 TVLP 1.0 Schema。

缺少这些新字段的历史 TVLP 1.0、CSV、JSONL 和 TensorBoard 仍能导入、搜索、绘制或作为单点结果显示。`metric_groups` 只改变呈现，不得改动原始数值和 key。不要要求训练端主动连接 Viewer。
