## 本次必须解决的用户问题

- 大初始 Loss 把后期曲线挤成一条直线。必须实现全程、后期聚焦、对数、自定义范围及可靠纵轴自动适配，并给出实测截图；不能只把 `scale` 改成 true。
- 指标名称不可读。必须建立来源可追溯的指标语义解析器。`train/epoch_QUIVALENT` 在未确定真实定义前不得猜测公式或翻译成已知含义；中文名、解释、单位、优化方向、原键应可查看。
- 实验命名混乱。新 TVLP v1.1 标准输出必须包含**数据说明＋模型架构＋改动方案＋训练目标**四个结构化字段，自动生成摘要名；历史日志只读兼容且不补造元数据。训练 Agent 接入规范必须同步升级。
- 最基础的监控信息默认缺失。打开 Run 就要看到**训练时长/日志跨度（明确区分）、Epoch/Step、Train Loss、Validation Loss、最佳验证指标和当前 LR**；若原始数据没有，显示“未记录”，不得伪造。
- UI 仍像堆叠的管理后台。必须采用成熟设计组件，建设**唯一可调整宽度的实验侧栏＋右侧监控工作区**，让 Train/Val Loss 同图，主要验证曲线在首屏，预测结果可直接进入；原始日志、技术字段和调参控件只在高级区出现。保留 ECharts，不为视觉改造重建整个后端。
- **新增 P0：海量指标不能再平铺成按钮。** 截图中大量 `combo_SWIR_pair/*` 只有 1 个点却被当作可选训练曲线。必须按契约 C10 实现**可搜索/分组/分页的指标浏览器**，分离连续训练曲线、系统性能与单次评估；支持自由选择与保存自定义图表，选中指标必须真实显示，不能 `chartLimit` 静默截断。未知科学含义不得猜测。

## 执行要求

按照 `02_Training_Viewer_Implementation_Plan.md` 阶段 0→5 **直接实施代码**，每阶段可运行、可测试、可回滚。优先复用 Apache ECharts、shadcn/ui/Radix、react-resizable-panels、TanStack Table 等成熟组件，先核查版本和许可证，保持只用一种主要设计系统。不准为了展示而伪造训练曲线。

先建立失败用例与截图基线，再修复后端摘要及指标解释，接着改曲线，重建前端与可搜索指标浏览器，最后升级 TVLP 1.1 Writer/Schema/Validator/Agent 文档并做真实联调。整个过程**不允许修改用户历史日志、不允许让训练端强制连接 Viewer 服务、不允许把 Viewer 的 SQLite 索引变成唯一事实来源**。

## 验收门槛
